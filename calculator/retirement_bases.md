# 养老金计发基数配置

页面使用 [`retirement_bases.js`](retirement_bases.js) 中的人工维护数据快照，不会实时查询各地网站。目前没有接入全国统一的官方计发基数查询入口。新增或更新数字时，请先核对当地人社、政府或税务部门发布的原文，再修改配置文件；保存后刷新页面即可生效，无需编译。

## 字段怎么填

`checkedAt` 是这份配置最近一次核对的日期，格式为 `YYYY-MM-DD`。完成核对后更新它，页面底部会显示此日期。单条数据的 `year` 是**计发基数适用年度**，不一定与 `checkedAt` 相同。

`bases` 按省级代码存放数据。`default` 是该省多数城市适用的值；如果城市单独公布数值，在 `cities` 中按城市代码覆盖。代码可在 [`retirement_regions.js`](retirement_regions.js) 查找。直辖市也保留城市选择，通常使用对应的 `default`。

每条有效记录包含：

| 字段 | 含义 |
| --- | --- |
| `year` | 适用年度，例如 `2025` |
| `base` | **每月**计发基数，单位元，例如 `7999` |
| `source` | 支持该数值及适用范围的官方文件网址 |
| `detail` | 可选；折算方式或适用范围说明 |
| `valueSource` | 可选；计发办法与金额分属两个官方文件时，填金额来源网址 |

例如，安徽省的现有记录：

```js
"34": {
  default: {
    year: 2025,
    base: 7999,
    source: "https://hrss.ah.gov.cn/public/6595721/80776356.html"
  }
},
```

如果省级文件明确排除某市，而该市尚无核实数据，应将该城市设为 `null`，避免误用省级金额；可在 `cityNotes` 写原因。山东菏泽市（`3717`）是现有示例：

```js
"37": {
  default: { year: 2025, base: 7831, source: "官方文件网址" },
  cities: { "3717": null },
  cityNotes: { "3717": "省级数值不适用于此市，请按当地文件填写。" }
},
```

如果核实了城市单独适用的基数，将 `cities` 中的 `null` 换成完整记录即可。只有官方明确说明全省统一适用时，才把数值放入 `default`。没有核实的省份保持 `{ default: null }`，页面会留空供使用者手动输入。

对暂缺数据的地区，可选填 `note` 说明原因，以及 `inquiry: { label, url }` 提供官方咨询入口。河南省目前使用此方式；咨询入口不是计发基数金额来源，核实金额后仍需填写对应的 `year`、`base` 和 `source`。

## 录入前核对

1. 确认文件说的是**企业职工基本养老金计发基数**，并核对待遇领取地、适用年度及特殊城市或人员类别。缴费基数、缴费工资上下限、养老金调整金额不能直接当作计发基数。
2. 官方文件只给出年度金额时，用年度金额除以 12，按元保留两位小数，并在 `detail` 记下原始金额与折算方式。若由其他指标推算，需同时保留计发办法和指标来源。
3. 将官方文件网址填入 `source`；如数值与计发规则来自不同文件，再填 `valueSource`。链接应直接指向可核对的官方页面或文件。
4. 更新 `checkedAt`，刷新页面并选中对应地区，核对自动填入的金额、年份、说明和链接。配置只保留每地当前录入的一条记录，旧年度数据不会自动保留。

截至 2026-09-30，以下省级代码仍为 `null`：`14` 山西、`15` 内蒙古、`41` 河南、`42` 湖北、`46` 海南、`50` 重庆、`51` 四川、`61` 陕西、`62` 甘肃、`65` 新疆。另有山东菏泽市单独留空。找到适用的官方文件后，可逐条补入，无需等所有地区齐全；补录时同步更新这份清单。
