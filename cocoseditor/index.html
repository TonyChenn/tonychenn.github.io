FAQ

Before you connect.

A runtime view of your game, with a clear boundary between live edits and your project files.

What is CocosEditor?

CocosEditor is a runtime editor and debugging tool for Cocos2d-x. It connects to an SDK-integrated game to inspect the live hierarchy, edit supported component properties, browse assets, inspect logs, and expose supported runtime capabilities through MCP.

Does CocosEditor modify my Cocos2d-x project?

Initial Runtime SDK integration requires native project configuration and lifecycle integration. Once connected, Hierarchy and Inspector operate on the running game's state. Runtime property edits do not automatically rewrite your project source or scene resource files.

Does it require an SDK integration?

Yes. The game must integrate the CocosEditor Runtime SDK for its target platform, with a version matching the editor. This requirement applies to C++ and Lua projects.

Can runtime changes be saved back to the project?

Runtime changes are not automatically written back to Cocos2d-x project source code, CSB files, CSD files, or other scene resources. Treat Inspector edits as changes to the current running session. Apply the final values in your own code or resource authoring workflow when you want them to persist.

Does it support Lua projects?

Yes, for compatible Cocos2d-x projects with native Runtime SDK integration. You can inspect live Cocos nodes and supported component properties, including nodes created by Lua. This is not a promise of arbitrary Lua variable inspection or a full Lua source debugger.

What is MCP integration?

MCP stands for Model Context Protocol. CocosEditor exposes tools that compatible AI clients can use to inspect and interact with the connected runtime. It assists development and debugging; available tools depend on the runtime's supported capabilities. See the MCP API reference for configuration and operation details.
